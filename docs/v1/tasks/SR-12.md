# SR-12 — Plugin: marketplace, refine and write-spec skills

Phase 1 · Needs: SR-9 · Implements: SRD-15, SRD-20 (authoring side), SRD-11 (sizes in specs)

The spec skills ship with specrun as a Claude Code plugin: `refine` (unchanged in spirit,
project-agnostic) and `write-spec` rewritten for the new format — `spec.json` with sizes, a
spec-specific `TASK_PROMPT.md` that adds only rules (the protocol is built in), no
PROGRESS.md / run.env to author.

## Decisions

- **SRD-15** — the repo root is a Claude Code marketplace (`.claude-plugin/marketplace.json`)
  with one plugin in `plugin/` (skills `refine`, `write-spec`, `feedback`), checked by
  `claude plugin validate`. Project specifics (commit scopes, terminology) stay in each
  project's CLAUDE.md.
- **SRD-20** — `spec.json`: `{ title, branch?, tasks: { id, title, phase, needs, model
("default" | "strong"), size ("S" | "M" | "L") }[] }`; every task has `tasks/<id>.md`.
- **SRD-11** — write-spec assigns each task a size S/M/L; ranges come from the project's
  `specrun.config.json` (`specrun stats --calibrate` tunes them).
- **SRD-18** — the protocol (`src/session/protocol.md`) is built in; a spec's `TASK_PROMPT.md`
  only adds spec-specific rules and invariants.

## Read first

- `CLAUDE.md`.
- The current skills to port, copied into the bootstrap folder: `tools/skills/refine/SKILL.md`,
  `tools/skills/write-spec/SKILL.md` and `tools/skills/write-spec/templates/*`.
- `src/session/protocol.md` — what the agent already gets (don't repeat it in templates).
- `src/spec/specSchema.ts`, `src/config/configSchema.ts` — the formats the skill writes.
- `claude plugin init --help`, `claude plugin validate --help` — scaffold and validation (run
  `claude plugin init` in a temp dir to see the generated layout; don't guess manifest fields).

## Changes

- New `.claude-plugin/marketplace.json` (marketplace `specrun`, one plugin `specrun` with
  `source: "./plugin"`) and `plugin/.claude-plugin/plugin.json` (name `specrun`, version from
  `package.json`, description) + `plugin/README.md` (install: `/plugin marketplace add
<repo>` then `/plugin install specrun@specrun`).
- New `plugin/skills/refine/SKILL.md`: the old skill without rebel-industry specifics (no MUI,
  i18n, Firestore examples — generic examples), still writing decisions in a shape write-spec
  can paste, still producing the file map.
- New `plugin/skills/write-spec/SKILL.md` + `templates/` (`README.md`, `spec.json`,
  `TASK_PROMPT.md`, `task.md`): same principles (self-contained briefs, Read first lists,
  cutting rules with turn targets now expressed as sizes), but: writes `spec.json` (validate by
  `specrun status <spec>`), no PROGRESS.md / run.env, `model: strong` replaces OPUS_TASKS,
  the brief's "Implementation notes" section is gone (notes come from `complete_task`), and
  the final check is `specrun status <spec>` loading without errors (it validates
  `spec.json`, ids, needs, cycles and briefs) instead of the old `--dry-run`. Commit message for the spec stays `docs(<scope>): add <name> spec`.
- `package.json` `files` already includes `plugin`; add `.claude-plugin`.

## Done when

- `claude plugin validate .` and `claude plugin validate plugin` pass (paste the output into
  the notes).
- New `src/plugin/templates.spec.ts`: the `spec.json` template (placeholders replaced by sample
  values in the test) parses with `SpecSchema`; every skill folder has a `SKILL.md` with `name`
  and `description` frontmatter.
- `tools/spec-verify.sh` green.
