# SR-10 — CLI: stats, calibrate, deviations, analyze

Phase 1 · Needs: SR-8, SR-9 · Implements: SRD-11 (calibration), SRD-12 (reporting), SRD-13/14 (commands), SRD-16 (JSON outputs)

Read-only views over the event logs of one or all specs: where runs spend turns and tokens,
how sizes calibrate, which deviations agents reported — human tables and `--json` for the
feedback skill.

## Decisions

- **SRD-11** — `specrun stats --calibrate` suggests ranges per model × size from history:
  turns p10–p90, usd p90, only with ≥ 3 samples (otherwise "not enough data (n)").
- **SRD-12** — overruns are only recorded (`budget.exceeded`); stats show them.
- **SRD-14** — `specrun analyze --reindex [spec]` recomputes analytics from the transcripts and
  appends new `analytics.session` events (higher `analyzerVersion`).
- **SRD-16** — the feedback skill reads `specrun stats --json`, `specrun deviations --json` and
  `specrun analyze --json`; their JSON shapes are a contract: zod schemas exported and
  documented in `docs/json-output.md`.
- A "sample" for calibration = one task that reached `done`: its totals over all segments.

## Changes

- New `src/stats/aggregate.ts` (pure): `taskSamples(specs)` → `{ spec, task, model, size,
turns, costUsd, peakContext, sessions, verifyRounds, deviations, budgetExceeded }[]`;
  `groupStats(samples, by: 'task' | 'model' | 'size' | 'spec')` → count, sum and p50/p90 of
  turns, cost, peak context; `calibrate(samples, sizes)` → per `model × size` current range,
  suggestion, n; `percentile(values, p)` (nearest-rank).
- New `src/cli/commands/stats.ts`: `specrun stats [spec...] [--all] [--by <dim>] [--calibrate]
[--json]` — default: the current repo's specs; table formatting shared with `status`.
- New `src/cli/commands/deviations.ts`: `specrun deviations [spec...] [--kind <kind>] [--json]`
  — from `lastCompleted` of done tasks and from `task.completed` of blocked ones; grouped by
  kind with counts, each line `spec/task [kind] decision: what — why`.
- New `src/cli/commands/analyze.ts`: `specrun analyze [spec] [--task <id>] [--reindex]
[--json]` — without `--reindex` prints per task the latest metrics summary (peak context,
  top 5 files by result size, re-reads, unread Read-first files, phase split marked "estimate");
  `--reindex` re-analyzes every transcript found for the spec (missing files → warning) and
  appends events (refuses while a run holds the lock).
- New `src/stats/jsonOutput.ts`: zod schemas `StatsJson`, `DeviationsJson`, `AnalyzeJson`
  (each `{ version: 1, generatedAt, … }`) used to build and test the outputs.
- New `docs/json-output.md`: the three shapes with a short example each.

- New `src/stats/aggregate.ts` (`taskSamples(SpecInput[])`, `groupStats`, `calibrate`, `percentile`, `SpecInput`, `TaskSample`, `MIN_CALIBRATION_SAMPLES`), `src/stats/jsonOutput.ts` (`StatsJsonSchema`, `DeviationsJsonSchema`, `AnalyzeJsonSchema`), `docs/json-output.md`.
- New `src/cli/commands/{stats,deviations,analyze}.ts` (registered in `program.ts`), shared `src/cli/table.ts` (moved out of `status.ts`) and `src/cli/specInputs.ts` (`loadSpecInputs(repoRoot, config, names)`, worktree events first). Test helper `test/fixtures/taskEvents.ts` (`doneTask`).
- Deviations: `stats --all` is an alias of the default (all specs of this repo) — there is no cross-repo store; `--by` defaults to `model`. Model in samples/calibration is the task's `model` alias (`default`/`strong`) from spec.json, not the resolved model id.
- `analyze` without a spec covers all specs, so `AnalyzeJson` is `{ specs: [{ spec, tasks }], reindexed, warnings }` (brief implied a single spec). Per task, segments are merged: max peak context, summed re-reads/phases, top-5 files by summed result size, unread = Read-first entries never read in any segment.
- `--reindex` walks `session.finished` segments (id + segment), builds the transcript path as the runner does, appends one event per transcript with the current `ANALYZER_VERSION` (no skip when the version is unchanged; `latestMetrics` lets the later event win). Missing/broken transcripts → warning (stderr, or `warnings` in JSON). Lock check uses the pid in `.specrun/locks/<spec>.lock`.
- `deviations` reads `lastCompleted` of done tasks and the latest `task.completed` of blocked ones.
- No older docs described behaviour SR-10 supersedes, so no "superseded" notes were added.
