# SR-13 — Feedback skill

Phase 1 · Needs: SR-10, SR-12 · Implements: SRD-16

A skill that turns run data into concrete proposals: which briefs, prompts, test docs or size
ranges to change, with the evidence behind each. A first version — it is expected to be
revised once real specrun runs exist.

## Decisions

- **SRD-16** — skill `feedback` reads `specrun stats --json`, `specrun deviations --json` and
  `specrun analyze --json`, and proposes concrete edits (spec-specific `TASK_PROMPT.md`, the
  write-spec skill, project test docs, CLAUDE.md, size ranges) as a numbered review list with
  evidence; it applies nothing without the user's OK.
- **SRD-13** — the analytics: context curve, tool/file costs, re-reads, brief adherence, phases
  (estimate).

## Changes

- New `plugin/skills/feedback/SKILL.md` (≤ 150 lines). Workflow:
  1. Scope: which specs (default: those with runs since the last feedback, or the ones the user
     names); collect the three JSON outputs.
  2. Signals, each with a threshold and what it suggests:
     - unread Read-first files / many extra reads → brief Read-first lists off (write-spec);
     - top files by result size read whole, repeated re-reads → reading guidance (`sed -n`,
       grep) in the project's CLAUDE.md or the spec prompt;
     - large Bash outputs from test/verify commands → quieter commands / verify summary;
     - phase `test` + `fix` > 40 % of tokens → test docs (recurring `test-trap` deviations
       become recipes);
     - deviations by kind: `spec-bug` / `ambiguity` clusters → write-spec analysis rules;
       `scope` → cutting rules; `constraint` → CLAUDE.md;
     - sizes: tasks outside their range, `stats --calibrate` suggestions → config `sizes` and
       write-spec's sizing guidance;
     - peak context outliers → split rules.
  3. Output: a numbered list `N. <target file> — <proposed change> — evidence: <spec/task,
numbers>`, most token-saving first, then ask which to apply (AskUserQuestion multi-select
     when available) and apply only the chosen ones.
  - Never edits `events.jsonl` or `spec.json`; never reruns tasks.
- `plugin/README.md`: list the skill.
