# SR-11 — Ink dashboard

Phase 1 · Needs: SR-9 · Implements: SRD-2 (dashboard)

`specrun run` in a terminal shows a live dashboard instead of log lines: task list with status
and stats, what the agent is doing right now, usage windows and the countdown while waiting.

## Decisions

- **SRD-2** — Ink dashboard during `run` when stdout is a TTY; the line reporter otherwise or
  with `--no-ui`.

## Changes

- Dependencies: `ink`, `react`; dev `@types/react`, `ink-testing-library`. `tsconfig.json`:
  `"jsx": "react-jsx"`; `.tsx` files only under `src/ui/`.
- New `src/ui/dashboardStore.ts` (pure): `createDashboardStore(spec, initialState)` →
  `{ apply(update), snapshot(), subscribe(fn) }` — folds `RunReporter` updates into a view
  model (rows per task with status icon `✔ ▶ · ✖ ⏸`, model, turns, context, cost, "needs X"
  for blocked-by-deps, current activity line, usage line, waiting countdown target, last 5 log
  lines). Throttles notifications to ≥ 100 ms.
- New `src/ui/Dashboard.tsx` + small components (`TaskRow.tsx`, `UsageBar.tsx`) rendering
  the snapshot; countdown recomputed from `now()` each second; width-aware truncation of long
  paths (keep the file name).
- New `src/ui/createInkReporter.ts`: `createInkReporter(spec, state, { stdout })` →
  `{ reporter: RunReporter, unmount() }`.
- `src/cli/commands/run.ts`: Ink reporter when `stdout.isTTY && !noUi`, otherwise the line
  reporter; unmount on finish (before printing the final summary line).

## Implementation notes

<!-- Filled in by the implementing agent: files, exported names, deviations. -->

Implemented interactively on 2026-11-13 after a real run (`rebel-industry`, `character-traits`)
looked stuck: no output while the worktree and `npm ci` were set up, then 15 s of silence.

- Dependencies: `ink@^8`, `react@^19.3`; dev `@types/react@^19.3`, `ink-testing-library@^4`.
  `tsconfig.json` `"jsx": "react-jsx"`; `tsconfig.build.json` also excludes `*.spec.tsx`.
- `RunReporter` gained `plan({ spec, events })` (once, after the worktree exists, before the
  first event) and `phase(RunPhase)` — `worktree | setup | usage | agent | verify | commit`.
  `ensureWorktree` takes `onProgress` (only when it creates the worktree). `runSpec` warns
  `usage probe failed — running without limit data` once per failure streak.
- `src/cli/eventLines.ts`: `createEventFormatter()` (milestone lines as `Segment[]` with a
  `Tone`), `clockTime`, `usageText`; shared by `lineReporter.ts` and the dashboard log. New
  lines: task title on `session.started`, `usage: …` on `usage.snapshot`, `creating worktree`
  and `setup:` phases.
- `src/ui/dashboardStore.ts`: `createDashboardStore({ now })` is itself the `RunReporter` plus
  `snapshot(): DashboardView`; rows come from `deriveState` over the plan's events + this run's.
- `src/ui/Dashboard.tsx` (+ `TaskRow.tsx`): `<Static>` milestone log above a round box —
  header `title · phase N · done/total done · spinner activity · elapsed` (the running task's
  time), task rows, `🔧` line of the running task (`truncate-start` keeps the file name),
  footer with usage or the wait countdown. `formatElapsed`.
- `src/ui/createInkReporter.ts`: `createInkReporter({ stdout, now? })` → `{ reporter,
unmount() }`; redraws every `TICK_MS` (200 ms), which also throttles tool-call bursts;
  `exitOnCtrlC: false` so SIGINT still aborts gracefully. `run.ts` picks it when
  `--ui && isTTY` (`RunCommandOverrides.isTTY`, `.createInkReporter`) and unmounts before
  printing the final message (and again in `finally`, a no-op).
- Deviations: no `subscribe` / 100 ms store throttling — the 200 ms render tick reads
  `snapshot()` instead; no `UsageBar.tsx`, the footer is one `<Text>`. The log keeps the
  milestones (Q: history stays in the scrollback), tool calls only show in the box.
- `probeUsage` waits for `query.initializationResult()` instead of the `system:init` message,
  which SDK 0.3.319 no longer sends to an idle streaming session (every probe timed out).
