# Feature Map Bootstrap

> Archived on 2026-11-17 by `specrun archive`. The full spec folder (briefs, prompts, run log) is in git at `5ca9f06`: `git ls-tree -r --name-only 5ca9f06 -- docs/003-feature-map-bootstrap`.

Creates a feature map for an existing repository. The `feature-map` skill gets a bootstrap mode:
an inventory of cheap signals, then a proposed feature list that the user approves, then draft docs
per area, assembly and `specrun features check`. specrun's own map is created unattended as
drafts. For rebel-industry, the user runs the skill there (rollout below).

## 2. Analysis

### Inputs a bootstrap can use cheaply

- `CLAUDE.md` (layout and conventions), entry points (routes, CLI command registry, public
  exports), top-level source folders, i18n namespaces (top-level keys usually match features),
  data collections and security rules, archived spec READMEs (`<specsDir>/archive/*/README.md`),
  existing docs, e2e / integration test names.
- Granularity is the decision with the most impact and is cheap to review as a list, before any
  doc is written.

### specrun's own code (for FB-2 / FB-3)

Layout per `CLAUDE.md`:

- `src/` folders: `cli/` (commands), `config/`, `spec/`, `events/`, `progress/`, `git/`,
  `verify/`, `limits/`, `session/`, `runner/`, `analytics/`, `archive/`, `review/`, `stats/`,
  `ui/`, `process/`.
- From specs 001/002: `plan/` and `features/`.
- Skills in `plugin/skills/`.
- User-facing docs in `README.md`.
- The v1 design spec is `docs/v1/README.md` (decision log `SRD-*`).

### Side effects to keep in mind

- specrun's map is written without the user's review gate, so every doc stays `draft` (FBD-4); the
  feature list (FBD-5) was agreed with the user beforehand. The user reviews it in the branch before
  merging.
- `specrun.config.json` of the specrun repo gains a `features` verify step. The step runs the CLI
  from source (`npx tsx src/cli/main.ts`), because the installed `specrun` may be older than the
  code being verified.

## 6. Out of scope

- An audit mode comparing the map with code changed outside specrun.
- Creating rebel-industry's map from this repo.

### 6a. Rollout to rebel-industry (manual, after 001–003 are merged)

1. Rebuild and link specrun (`npm run do`), update the plugin in Claude Code.
2. In rebel-industry open Claude Code and run `/specrun:feature-map` ("create the feature map").
3. Review the proposed areas and features. The inventory should use `apps/melior/app/routes.tsx`,
   the CLAUDE.md "Code Layout", the top-level keys of `apps/melior/app/locales/cs/common.json`,
   `firestore.rules`, `docs/archive/*/README.md`, `docs/board/*`, `docs/character/*` and the e2e
   tests.
4. Let the drafts be written per area. Existing `docs/board/0x-*.md` are linked from feature
   docs, not copied.
5. Decide on the proposals: trim the CLAUDE.md "Code Layout" section to a pointer to the map; add
   `npx specrun features check` to rebel-industry's verify steps.
6. Commit the map. From then on write-spec adds the map-update task to every spec.
