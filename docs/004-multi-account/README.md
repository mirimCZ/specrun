# Multiple Claude accounts

specrun can run its agent sessions on more than one Claude subscription. Accounts are listed in
priority order in a new global config, `~/.specrun/config.json`. Each account has its own limits,
and a repo can override them. A run uses the priority account and moves to the next account when
the priority one runs low. With `--burn` it also moves on when only the 5-hour window is low;
without it, it waits for the reset. With no global config, specrun behaves exactly as it does
today.

in [tasks.yaml](tasks.yaml)).

> **Precondition (manual check, once):** run `claude setup-token` while signed in to the second
> account, then `CLAUDE_CODE_OAUTH_TOKEN=<token> claude -p "hi"`. Check that `/status` (or the
> usage shown in claude.ai) reports the second account. Then resume a session started without the
> token, using the token (`claude -r <id> -p "continue"`). If the resume fails, MAD-10 changes to
> "start a new session with a handoff prompt" before MA-5 runs.

## 2. Analysis

### Mechanism

The Agent SDK's `query()` starts the Claude Code CLI as a child process. `options.env` replaces
that process's environment (default: `process.env`). The CLI signs in with
`CLAUDE_CODE_OAUTH_TOKEN` when the variable is set; `claude setup-token` creates a long-lived
token for a subscription. `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` take precedence over the
OAuth token. The config dir stays `~/.claude`, so transcripts, settings, plugins and session
resume are shared between accounts. Prompt cache is per account: the first turn after a switch is
uncached.

### Where things are today

- Config: `src/config/configSchema.ts` (`LimitsSchema`: `sessionMinLeft` 15, `weeklyMinLeft` 5,
  "% left" thresholds) and `src/config/loadConfig.ts` (`loadConfig(repoRoot, deps)`, `~/` expansion
  of `transcriptsDir`). No global config exists. `~/.specrun/` already holds `runs/`.
- Policy: `src/limits/policy.ts` `decide(snapshot, limits, now)` → go / wait session-low / stop
  weekly-low; `waitTarget`, `limitHitTarget`.
- Session: `src/session/sdkSession.ts` builds `options` for `query()` (no `env`);
  `src/session/agentSession.ts` `SegmentInput`; `src/session/probeUsage.ts` runs an idle `query()`
  ($0) for the usage windows.
- Runner: `src/runner/runSpec.ts`. `RunSpecDeps.probeUsage` is a single probe. `latest` is one
  `UsageSnapshot`. `pauseCheck` runs before every segment (SRD-10, `SNAPSHOT_MAX_AGE_MS`). A
  `limit` outcome waits for the reset and resumes the same session with `limitResumePrompt()`.
- CLI wiring: `src/cli/commands/run.ts` lines 213–222 (`createSdkSession()`,
  `probeUsage({ cwd: repoRoot })`). `plan.ts` / `review.ts` start the interactive `claude` with
  `env: deps.env` (`runInteractive`).
- Events: `src/events/eventSchema.ts` (`usage.snapshot`, `limit.wait`, `session.started`,
  `session.finished`, union `EventSchema`). UI: `src/ui/dashboardStore.ts` (`UsageView`, one
  usage), `src/cli/eventLines.ts` (`usageText`). Stats: `src/stats/aggregate.ts` +
  `src/stats/jsonOutput.ts` + `src/cli/commands/stats.ts`; commit `7531d9b` (verify timings) is
  the pattern for a new stats section.

### Side effects to keep in mind

- Without a global config there is exactly one implicit account; every existing test of the
  runner, CLI, UI and stats must pass unchanged (the regression net for MAD-6).
- The token is a secret: it must never reach events, logs, transcripts, error messages or
  `PROGRESS.md` (MAD-15).
- `options.env` replaces the whole environment: always start from a copy of the base env (MAD-16).
- The repo config is checked in and shared: account names in `limits.accounts` may not exist on
  another machine (MAD-17).
- Events written before this spec have no `account`. Readers treat a missing field as
  `default` (MAD-12).
- The probe costs nothing but takes up to 15 s per account (`PROBE_TIMEOUT_MS`).

## 3. Decision log

Agreed with the product owner on 2026-11-20 (see [Resolved questions](#5-resolved-questions)).
Prefix `MAD-`.

| ID     | Topic                              | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------ | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MAD-1  | Mechanism                          | An account with a token runs its CLI processes (task sessions, usage probes, interactive `claude` of plan / review) with `CLAUDE_CODE_OAUTH_TOKEN=<token>` in the child env. specrun never sets `CLAUDE_CONFIG_DIR`; `~/.claude` stays shared.                                                                                                                                                                                                                                                                                   |
| MAD-2  | Where accounts live                | Global config `~/.specrun/config.json` (`GLOBAL_CONFIG_FILE`), strict zod schema: `{ "accounts": [{ "name", "token"?, "limits"? }] }`, `accounts` defaults to `[]`. `name` matches `^[a-z0-9][a-z0-9-]*$` and is unique. `limits` is a partial `{ sessionMinLeft?, weeklyMinLeft? }` (0–100). A missing file is an empty config; invalid JSON or schema → `SpecrunError('config-invalid', '~/.specrun/config.json is invalid', issues)`. The repo config gets `limits.accounts`: a record `name → partial limits`, default `{}`. |
| MAD-3  | Limit precedence                   | Per field: repo `limits.accounts.<name>` > global `accounts[].limits` > repo `limits.sessionMinLeft / weeklyMinLeft` > defaults (15 / 5).                                                                                                                                                                                                                                                                                                                                                                                        |
| MAD-4  | Priority                           | The order of `accounts` is the priority; the first account is the priority account.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| MAD-5  | Token source                       | `token` is `{ "env": "<VAR>" }` (value of that variable) or `{ "command": "<shell command>" }` (trimmed stdout; run through `/bin/sh -c`, or `cmd.exe /d /s /c` on win32, with a 10 s timeout). An account without `token` uses the system login (env unchanged); at most one account may omit it. A missing / empty variable, a non-zero exit, a timeout or empty stdout → `SpecrunError('account-token', 'account <name>: …')` whose details never include stdout.                                                             |
| MAD-6  | No global config                   | No accounts configured → one implicit account `default` (`IMPLICIT_ACCOUNT`), system login, limits from the repo config. Output, events (apart from the `account` field) and exit codes stay as today.                                                                                                                                                                                                                                                                                                                           |
| MAD-7  | Session-low                        | `specrun run -b` / `--burn`: an account whose 5-hour window is low is skipped in favour of the next account that can go. Without `--burn`, the run waits for that account's session reset (today's behaviour), even if a later account could go.                                                                                                                                                                                                                                                                                 |
| MAD-8  | Weekly-low                         | An account below its weekly minimum is always skipped, with or without `--burn`. When every account is weekly-low, the run stops as `paused-weekly` (exit 75).                                                                                                                                                                                                                                                                                                                                                                   |
| MAD-9  | Choosing the account               | Every task starts by choosing an account in priority order, so a task after a reset runs on the priority account again. Within a task the account is sticky: later segments (verify-fix, nudge, limit-resume) keep it as long as it can go, and move on (in priority order) only when MAD-7 / MAD-8 / MAD-10 force it.                                                                                                                                                                                                           |
| MAD-10 | Limit hit in a session             | A `limit` outcome blocks that account until its reset target (`waitTarget` / `limitHitTarget`). With `--burn`, the task resumes the same session on the next account that can go. Without `--burn`, it waits for the reset and resumes on the same account, as today. If no account can go, it waits for the earliest target. Waits caused by a blocked account keep the reason `limit-hit`.                                                                                                                                     |
| MAD-11 | `--account <name>`                 | On `run`, `plan` and `review`: use only this account (no switching). Unknown name → `SpecrunError('account-unknown', …)` listing the configured names. `plan` / `review` without the flag use the priority account.                                                                                                                                                                                                                                                                                                              |
| MAD-12 | Events and stats                   | `session.started`, `session.finished`, `usage.snapshot` and `limit.wait` get an optional `account: string` (always written by the runner; missing = `default`). New event `account.switched { task, from, to, reason: 'weekly-low' \| 'session-low' \| 'limit-hit' \| 'priority' }` when a segment runs on another account than the run's previous segment. `specrun stats` adds an ACCOUNTS table (per spec and account: segments, turns, cost) and `--json` `accounts`.                                                        |
| MAD-13 | Dashboard                          | The dashboard and log lines show the active account and the latest known 5h / weekly % of each account, plus a line on each `account.switched`. With only the implicit account, the output is unchanged.                                                                                                                                                                                                                                                                                                                         |
| MAD-14 | `specrun accounts`                 | Lists the accounts in priority order. For each it shows the token source (`env VAR`, `command`, `system login`), the merged limits, and a probe result: 5h / weekly % left with resets, `token error: …` or `probe failed`. Exit 1 when any account failed.                                                                                                                                                                                                                                                                      |
| MAD-15 | Token safety                       | Tokens are resolved once per command start for the accounts it will use and kept in memory only. They never reach events, logs, transcripts, error messages or `PROGRESS.md`. A token error fails the command before any work starts.                                                                                                                                                                                                                                                                                            |
| MAD-16 | Child env                          | For an account with a token: a copy of the base env without `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and `CLAUDE_CODE_OAUTH_TOKEN`, then `CLAUDE_CODE_OAUTH_TOKEN=<token>` (`accountEnv`). For the system login: no override (the SDK / child inherits `process.env`).                                                                                                                                                                                                                                                        |
| MAD-17 | Unknown repo overrides             | A name in repo `limits.accounts` that the global config doesn't define yields a warning `limits.accounts.<name>: no such account in ~/.specrun/config.json`, never an error. The warning appears only when the global config defines accounts.                                                                                                                                                                                                                                                                                   |
| MAD-18 | First switch of a run              | The run's previous account starts as the priority account, so a first segment on another account emits `account.switched` with its reason (`weekly-low`, `session-low`). Decided in review on 2026-11-20 (MA-5).                                                                                                                                                                                                                                                                                                                 |
| MAD-19 | Reset format in `specrun accounts` | Resets are shown as relative durations (`resets in 1h 30m`, `resets in 3d 0h`), independent of the time zone. Decided in review on 2026-11-20 (MA-6).                                                                                                                                                                                                                                                                                                                                                                            |
| MAD-20 | `burn` option                      | `burn` is optional on `RunSpecOptions` / `RunAllOptions` (default `false`); the CLI sets it only with `-b`, so existing option assertions stay unchanged. Decided in review on 2026-11-20 (MA-5).                                                                                                                                                                                                                                                                                                                                |

## 6. Out of scope

- Separate config dirs per account (`CLAUDE_CONFIG_DIR`).
- Native Keychain / libsecret / Credential Manager sources (the `command` source covers them).
- Switching accounts within a task while its account can still go.
- Account data in `specrun archive`'s `history.json`.
- Commands that write the global config (adding accounts, storing tokens).
